4. 核心用户旅程

J1 从零安装并游玩

  1. 打开应用：读取本地数据；无实例时显示简明三步引导，先选择数据目录，再登录/浏览版本。
  2. “安装游戏”：正式版默认选中，显示列表更新时间与来源；快照需主动开启。
  3. 选择版本→可选一个兼容 Loader→实例名称与隔离目录→Java/空间预检。
  4. 右栏显示安装摘要：下载估算、缓存复用、预计磁盘占用、Java、资源来源；未知大小显示“估算中”，不能显示 0。
  5. “确认并安装”生成不可变安装计划；点击只创建一个任务。关闭向导不取消任务。
  6. 下载→校验→构建→提交实例；期间可以浏览其他页面。
  7. 完成进入实例详情；“启动游戏”预检账号与文件，启动后显示“运行中”和日志入口。

J2 给既有实例装 Mod

从实例“Mod 管理”进入，默认“已安装”；“发现 Mod”继承 MC/Loader 筛选。选中项目后展示版本、依赖、来源与更新范围；安装前一屏确认必需依赖。可选依赖默认不选。冲突或没有客户端兼容版本时阻止确认。下载不立即替换正在使用的文件；提交后更新锁文件。更新失败保留旧版。

J3 下载失败与恢复

任务卡显示阶段、已验证文件数、已传输字节、速度、来源与可执行操作。网络错误自动有限退避；超限转“需要处理”，显示最后错误和“重试失败项”。磁盘不足不盲重试，允许“更改目录并重新计划”或清理后继续。重启应用显示恢复提示，不自动运行未知状态的安装处理器。

J4 老实例迁入

选择 PCL 或 .minecraft 根目录→只读扫描→列出隔离方式、MC/Loader、大小、未知内容→选择实例和复制目标→核对磁盘空间→复制与校验→修复缺失依赖→用户重新登录→首次启动。源目录不变；不迁移注册表、凭据、PCL 可执行配置脚本。

6. 交互规则与文案

  • 用户显示名与磁盘目录 ID 分离；名称 1–64 字符，去首尾空格，禁止空名；内部目录只用 UUID，不因重命名改路径。
  • 全局默认：自动匹配 Java、实例内存 4 GiB（设备允许时）、下载总并发8/单域4；这些是产品默认值，需在 Windows 性能验收后调整，不宣称最优。
  • 任何“安装”显示目标实例和影响文件数；任何删除显示是否含 saves，并默认进入应用回收站，可恢复7天。清理永久删除需再次确认范围。
  • 启动前 Esc 取消预检；启动进程后 Esc 不杀进程。停止游戏先请求正常关闭，超时再显示强制结束确认。
  • 离线浏览与已有文件校验可用。仅先前成功验证的同一账号可进入受限离线启动路径；明确显示“离线，本次不刷新授权”，不能把 API403 或无权益转为离线成功。是否能运行取决于游戏版本，见状态机。
  • 启动按钮旁持久在线账号与实例信息；登录失效不偷偷改用其他账号。
  • 所有失败提示按“发生了什么→影响→可执行操作→详情码”组成。例如：“磁盘空间不足，安装尚未提交。释放至少 2.4 GiB 后继续。DISK_SPACE_LOW”。
  • 原型所有数据、速度、版本组合均为演示；登录/启动/网络/安装只演示交互，不执行真实系统操作。

React 只展示DTO和用户意图，不能持有refresh token、直接下载资源、自由读写磁盘或运行命令。Rust持有业务事实与所有网络/系统副作用。Tauri 2 只为主本地窗口授予具体能力；远程网页、Mod描述、登录站点不得获得IPC能力。来源：Tauri Capabilities。

网络下载内容、压缩包、JAR、版本JSON、外部目录、日志均视为不可信输入。自定义Rust命令不会因启用capability就自动得到充分校验，每个命令仍需验证实例ID、允许的状态、路径令牌与revision。

5. 事件契约与一致性

持久事件：event_id（单调序列）、entity_id、entity_revision、task_id?、kind、occurred_at（UTC）、payload、contract_version。持久kind见11第10节；task.progress是非持久通知，不使用event_id。

  • 命令持久提交后才发状态事件。先订阅并缓冲，再获取同一DB读事务内的snapshot+cursor，丢弃≤cursor的缓冲事件，再调用events.read补拉。握手、保留期和分页见11文档。
  • 进度通知每任务最多4次/秒，独立progress_seq并携execution_id；不增加实体revision，不用状态事件去重规则。每2秒或每8MiB持久化断点，取先到者。
  • 持久事件全局游标按实际记录补拉，不按实体筛选后猜缺口；实体revision只用于快照替换。通知可丢失，状态事件通过补拉恢复。超出保留窗口返回CURSOR_EXPIRED并重做握手。
  • commands accepted不代表任务完成；订阅失联不应把任务变失败。
  • 离线不清空目录列表；显示上次验证时间。缓存TTL只是设计默认：版本目录15分钟、Loader30分钟、Mod搜索5分钟；允许手动刷新，服务端cache头优先。

6. 启动解析管线

  1. 读取实例revision与锁文件；获取实例运行锁，校验路径、磁盘、组件状态。
  2. 递归解析inheritsFrom（循环检测/深度≤16），保留来源；缺失父版本产生补全计划，不能靠目录名猜mainClass。
  3. 评估libraries与arguments规则：有rules默认不允许，依序匹配更新allow/disallow；条件含OS、arch、版本regex和features。未理解的必要条件不得静默忽略。
  4. 合并继承链：标量由子覆盖；参数按字段规则追加；库用group:artifact:classifier:extension做冲突键，显式Loader替代优先；同坐标不同内容摘要冲突时拒绝；不是简单JSON深合并。
  5. 解析client jar、assetIndex、resources、logging、native classifiers；排除extract.exclude；每次运行独立natives临时目录，安全解压。
  6. 根据javaVersion.majorVersion、Loader约束、用户override求交集；启动前运行受控 java -version 探测缓存（路径+mtime+size，5秒超时）。不能只信文件名。
  7. 生成LaunchPlan：executable、args数组、受限env、cwd、classpath、资源/原生库路径、窗口参数；所有placeholder必须解析，未知必要变量阻断。
  8. 授权成功后在Rust内存注入access token等敏感参数；显示/导出均脱敏。Windows命令行长度接近限制时使用经过对应Java/版本验证的argfile或classpath JAR策略，不能随意改变旧版语义。
  9. 启动不经过cmd/PowerShell；捕获stdout/stderr，跟踪进程与子进程，按会话保留日志。

旧版minecraftArguments须使用经fixture验证的分词规则；不能按空格切字符串。资产virtual/map_to_resources、老版natives与旧Forge另有兼容适配，未通过样例前不能宣称通用兼容。

DB是真相源，lock文件是带revision与digest的可恢复投影。DB事务提交后生成临时lock并原子替换；中断导致lock落后时按DB重建；如果DB损坏，只能进入只读恢复模式，用户确认后从经过schema/路径/摘要校验的lock重建元数据。不得依据时间戳把外部lock覆盖进DB。

内容缓存与mutable game目录不得使用可写硬链接；v1依赖兼容投影统一复制，不使用hardlink/junction/symlink；只读属性不是可靠的隔离边界。运行前检查对象摘要。外部游戏可能修改库，因此必须允许投影重建，不把它作为缓存真相。

2. 通用字段

ID采用UUID；外部provider ID保留原样字符串，不转数字。时间存UTC RFC3339，UI按系统时区显示；elapsed使用单调时钟。size以u64字节表示、UI以MiB/GiB显示；所有IPC中的字节数、revision、event_cursor、progress_seq统一为十进制字符串（即便小于JS安全整数），禁止按数值大小切换类型。digest存algorithm+规范化小写hex。路径存path_id或根内相对路径；UI显示路径不直接作为授权路径。

revision为递增u64；所有变更需expected_revision。enum未知值在读展示时标记Unsupported，在执行时阻断，不能默认成Ready。可选值缺失与空字符串区分。

6. 关键事务与不变量

  • 每实例最多一个被接受的变更作业，commit计划时获取持久mutation lease直到成功/取消/失败安全回滚；游戏运行lease与该lease互斥。失败若保留未回滚现场仍占锁并转NeedsAction。无实例写意图的纯缓存预取可并发。第二个写/启动返回INSTANCE_BUSY并链接占用任务；不等到文件交换才发现冲突。
  • task.state=Succeeded要求所有必需步骤Succeeded且实例提交journal已完成，不能只看下载字节100%。
  • Instance=Ready要求已提交锁文件revision的所有必需组件可解析、必需对象存在并验过；运行前仍做廉价存在/指纹检查，必要时重哈希。
  • 登录密钥永不进SQLite/lock/event/前端；account.remove同时删除凭据引用与secret，失败记录可重试清理，不显示“已完全删除”。
  • 删除实例只移走自己UUID目录；不按用户可变名称递归删除。共享assets/libraries对象由引用计数+扫描GC回收。
  • GC先mark引用（活动任务、plan、实例、回收站/备份），再隔离候选，过24小时宽限期二次确认后删除；与下载和提交共享锁。引用计数不得单独作为唯一删除依据。
  • DB外键开启，WAL、busy timeout、短事务；大文件I/O与网络不得在DB写事务内等待。
  • 设置保存、事件记录、revision增加同事务；写失败保留旧值，UI不能先显示永久成功。

7. 文件系统与DB跨介质提交

不能假设SQLite事务会回滚文件。采用journal：Prepared（目标与旧manifest）→FilesStaged（所有文件已验证）→FilesSwapped（同卷原子rename/replace，旧文件移rollback目录）→DbCommitted（更新实例revision与引用）→Finalized（写lock投影、清理旧文件）。启动恢复逐条核查journal：DB未提交时回滚或继续已验证步骤；DB已提交时补齐投影，不回退已确认revision。发生无法判断的外部改动则RepairRequired，保留两份文件供核对。

跨卷迁移一律复制→校验→切换root指针→旧目录保留回退期，不将“跨卷move”当原子操作。

Task是用户可见作业（例如“安装远山生存”）；Step是可持久重试的执行节点；Artifact是跨任务共享的内容；Attempt是一次具体HTTP尝试。不要为每个asset渲染一张用户任务卡，可折叠显示子项。

Plan必须固定MC版本、Loader build、Java build、原始元数据摘要、对象哈希、URL来源、需要空间、目标root与base_revision。计划默认15分钟有效；过期只要求重新预检与确认差异，不强迫重下相同内容。上游列表改变不允许改变正在执行的计划。

同一scope+idempotency_key+payload摘要重复提交返回原task_id；同key不同payload返回IDEMPOTENCY_CONFLICT；同一摘要对象由单个写入者下载，其他步骤订阅共享结果。取消一个订阅者不能取消仍被其他任务引用的下载。无哈希资源只按任务隔离，不因同URL/文件名就跨任务信任。

2. 官方Minecraft解析与对象布局

  1. 根目录 https://piston-meta.mojang.com/mc/game/version_manifest_v2.json 提供latest、versions及每版本URL/sha1；保存原始字节，验证后再解析。
  2. 对版本JSON验证manifest给出的sha1；解析downloads.client、libraries.downloads/artifact/classifiers、assetIndex、logging.client、arguments与javaVersion。
  3. 对assetIndex验证version JSON中的sha1，展开objects；对象URL按 https://resources.download.minecraft.net/<hash前2位>/<hash>，文件内容验证sha1与期望大小。
  4. 下载libraries必须按Windows/x64和features评估rules；natives不是每个库都下载所有OS；日志配置文件同样是需要验证的对象。
  5. assets兼容布局按索引要求建立；旧版virtual/map_to_resources不能忽略。官方版本JSON、JAR与资源保持来源关系。来源见研究证据中的version样本与核实记录。

本次实测目录latest为release 26.3、snapshot 26.4-snapshot-5（2026-10-22的快照）；产品运行时必须重新读取，不将这些值写为恒定“最新”。SHA1作为上游内容完整性键使用，不把它解释为数字签名或免疫供应链攻击。

4. 下载协议

  • TLS强制验证；只允许HTTPS来源。认证域名不走内容镜像，不转发Authorization到跨域重定向。
  • 连接超时10秒、无进展读超时30秒；大文件不设过短总时限。可配置代理；不把证书失败归为超时。
  • 跟随最多5次重定向，每跳校验协议/主机/私网地址；支持上游必要CDN域，防止跳到file、localhost、内网/链路本地地址。
  • 从metadata取预期size/hash；Content-Length只是传输信息，不覆盖可信元数据。无size时允许下载但显示未知总量。解压大小另算。
  • 下载到staging里的.part，元数据记录已fsync/安全落盘的offset、强ETag或Last-Modified。checkpoint与文件长度不一致取安全已落盘边界，截断多余数据。
  • 恢复使用 Range: bytes=<offset>- 与合适的 If-Range。206必须核对Content-Range起止、总量与请求；200表示从头重下，不能追加。416先核对本地长度并全量哈希，成功才完成，否则从头；ETag或对象摘要改变时废弃旧part。
  • HTTP压缩与Range不混用：二进制请求identity编码；如服务不支持Range则重下整个对象。
  • 完整文件流式验证元数据中最强可用摘要（mrpack优先SHA512，Java包SHA256，官方MC至少SHA1）及size。失败文件隔离，不进入缓存。
  • 校验后同卷原子rename到不可变对象路径；已有对象再次比对已验证记录，冲突隔离并报HASH_COLLISION_OR_CORRUPTION。写入者lease释放后等待者可复用。

6. 空间、暂停与取消

空间估算＝未缓存下载字节+最大展开占用+安装输出+回滚旧文件+安全余量max(1GiB,10%)，以实际目标卷分别计算。总量未知时显示“尚不能确认，至少X”，并产生SPACE_ESTIMATE_INCOMPLETE阻断项；用户可确认一个明确的每卷空间预算上限后重新预览。新版plan固定预算、余量和确认项，下载/展开超预算即NeedsAction；禁止以未知=0提交。空间不足不允许commit。过程中持续检查空间阈值，用户外部写满磁盘时停到NeedsAction。

暂停：停止分配新步骤，活动HTTP可落盘checkpoint后停止；解压可在条目边界停止；文件交换提交阶段不可暂停，按钮禁用并说明“正在保存安装结果”。

取消：持久cancel_requested→取消子步骤→杀死本任务受控处理器（必要时确认）→回滚未提交文件→Canceled。缓存可保留；自有staging保留24小时后清理。已提交完成后“取消”不能变成删除实例。取消不会删除用户在外部放入的未知文件。

退出应用：有任务时提供“退出并保存进度 / 返回”；首版不提供后台常驻服务。由app.exit_request生成退出摘要，app.exit_confirm停止调度并等待安全停点。Committing不可强制退出，保持窗口并说明正在保存；普通步骤超过10秒进入等待/操作系统强退提示，不由应用主动退出尚未落盘事务。下次按Interrupted恢复，不误报Canceled。运行中的游戏按设置默认继续，关闭启动器时清晰提示日志跟踪可能中断。

7. Loader与Java安装

Fabric：用meta API查询game与loader兼容组合，获取固定build的profile/json；解析mainClass/libraries/arguments，继承原版资源。Fabric API是一个Mod项目，不等于Fabric Loader，按依赖计划另外安装。

Forge/NeoForge：下载官方安装器与相关依赖，读取install_profile与version JSON，在独立兼容根执行已支持的client processors（含sides、变量、Maven坐标、outputs）；若采用官方安装器运行模式，必须在临时兼容根中测试其客户端参数与launcher profile要求。所有安装器都是可执行代码，普通权限运行、限定工作目录、记录脱敏输出，不能声称是安全沙箱。失败检查输出hash，回滚临时结果，不能仅复制universal JAR宣称成功。Forge安装器源码。

Quilt：独立v3适配器，列为扩展；查询成功并不保证整个生态兼容。默认不作为新用户推荐Loader。

Java：优先已探测兼容本地/托管运行时，否则查询Adoptium assets API（Windows、x64、指定major、GA、hotspot、JDK ZIP）；固定返回build、package链接、SHA256与许可证信息，校验后安全解压到托管目录，再探测实际major/arch。不使用“latest二进制跳转URL”作为唯一可追踪锁。可后续支持官方runtime组件manifest，但M2先用一个验证过的Java提供商。Mojang版本中的java-runtime-delta/epsilon是组件标识，不能当下载URL。

8. Mod与整合包变更事务

Modrinth先取兼容版本列表，再确定具体version；项目搜索匹配不等于同一版本同时满足MC与Loader。required依赖递归求解，固定version优先；project-only依赖在实例约束下选候选并记录选择。optional默认不装；incompatible阻断；embedded视作已包含，不重复下载。环用访问集合检测；普通依赖环可折叠为强连通分量统一提交，版本约束无解时报冲突链。

本地识别读取fabric.mod.json、quilt.mod.json、META-INF/mods.toml、neoforge.mods.toml等有限大小条目；本地hash查Modrinth只在用户启用识别时进行，未知文件保留。不运行JAR“探测”。更新先diff→下载→验证→旧文件移回滚区→新文件替换→锁与DB提交。运行中只允许排队，退出后重新核查revision再提交。

mrpack：根部唯一modrinth.index.json，formatVersion=1、game=minecraft；安全解析files/hash/env/downloads/dependencies；跳过client=unsupported，optional给勾选；应用overrides后再client-overrides，不应用server-overrides；未知必需dependency阻断。路径规范、解压限制与来源域白名单见安全文档。下载缺文件时停NeedsAction，不能把不完整整合包标Ready。mrpack规范。

CurseForge：识别manifest和文件project/file ID；仅用户自己的获准API key可调用，不能内置他人key。作者禁止第三方下载或downloadUrl为空时显示文件清单与官方项目入口，用户补齐后按清单hash/可得元数据核验。通用ZIP仅支持识别后的格式；未知ZIP展示目录摘要，不自行猜测并运行脚本。

9. 恢复算法与可观测性

启动时：回收过期lease→将Running/Downloading步骤改Interrupted→核对journal→扫描part安全长度→验证已完成步骤输出→基于原plan建立剩余DAG→向用户展示“发现可恢复任务”。默认自动恢复普通可信下载，可设置关闭；安装器不确定中断状态需从干净工作区重跑相关步骤。写入实例的任务必须先恢复journal，不能直接重跑所有副作用。

每作业保留task_id、plan_digest、步骤耗时、来源、尝试次数、缓存命中与错误链；不记访问令牌或完整带签名URL。界面总进度由“已验证的已知总字节/字节总量”和当前阶段组成；不把构建时间塞入假百分比。下载完后显示“校验/安装中”，Ready才显示完成。

4. 启动状态

Idle→Preflight→RepairPlan?→RefreshingAuth→Resolving→PreparingNatives→Spawning→Running→Exited/Failed。首版“Running”仅表示受控进程创建且持续存活，不等同于“已进世界”；“启动成功”验收仍需观察游戏主菜单。可检测窗口/已知日志作为辅助信号，不硬编码跨版本日志句子作为唯一成功标准。

Preflight到Spawning前可取消；Spawning存在竞态：取消后若进程已创建，转“正在停止本次启动”并只作用于本次run。不能让UI回Ready而Java继续不可见运行。进程退出码0显示正常结束，非0或异常中止提示诊断；缺失日志显示“无法读取日志”，不能编造崩溃原因。

启动前缺文件：产生修复预览→用户确认→任务完成再启动。后台不静默下载大体积文件；允许用户在设置启用“小型依赖自动修复”，默认关闭。

6. 离线与服务降级

离线浏览：实例、已安装内容、日志、设置可用；搜索在线内容禁用并提供重试。曾成功在线验证的账号记录只作为受限离线使用资格，不当作永久授权证明；显式退出登录/移除凭据/明确无权益使资格失效。首次登录、API受限、账号明确被撤销不能自动进入离线模式。

本地离线启动不提供新的自定义身份、不修改UUID、不通过authlib替换绕过认证，也不承诺多人服务器可用。若目标游戏不能用该路径安全运行，则展示“当前版本不支持离线启动”，保留浏览/管理。是否允许过期Minecraft token参与本地运行须在M3固定版本验证后落实，未验证前不开放该按钮。

2. 路径与压缩包规范

对Windows不区分大小写与末尾点/空格的等价路径做冲突检测；拒绝NUL、控制字符、绝对盘符、UNC、\\?\/\\.\、冒号ADS、保留设备名(CON/PRN/AUX/NUL/COM1…/LPT1…)、路径段..和以斜杠开头的条目。反斜杠先按分隔符解析，不能只过滤../。Maven坐标的每一段只能落在约定目录，不接受URL当坐标路径。

写前验证目标在授权root内；不存在的目标逐级验证已存在父目录与reparse属性，创建/打开时防止跟随可疑重解析点，并在关键提交前重新校验。单次canonicalize不足以防止检查后替换。首版导入压缩包拒绝symlink/hardlink/reparse条目，拒绝重复及大小写冲突目标；普通用户自己选定root可记录稳定真实路径，但子路径仍逐级验证。

解压设计上限：单包10万条目、单条8GiB、总展开40GiB、压缩比>200时NeedsAction而非继续；这些是可调产品防护默认值，合法大包可在看见空间与来源后明确放宽。执行时流式统计真实展开量，不能只信ZIP头。清单JSON≤16MiB、版本JSON≤8MiB、Mod内元数据≤2MiB，超过限额报明确错误。所有路径在创建任何输出前完成静态预审。

3. 凭据与认证边界

v1选Windows DPAPI用户范围加密的本地secret文件作为CredentialPort；文件只在配置根secrets下，使用当前用户ACL与原子替换。每个secret用随机引用ID，DB只记录引用，禁止把密文发送前端。M0验证加密、轮换、写失败、删除失败与跨用户不可解密；若更换实现必须提交ADR。refresh token与代理/API key只以原生受保护secret保存；SQLite只存credential_ref。Minecraft/Xbox短期token只驻留Rust内存，必要时最小化保存策略另作ADR；不返回React、不放localStorage、不写启动脚本、不允许“一键复制完整启动命令”泄漏token。

游戏启动参数中的access token对同用户进程可能可见，这是Java客户端启动链路的残余限制；使用参数数组和日志脱敏不能使它对本机恶意软件保密。产品不要求管理员权限，不关闭证书校验，不收集Microsoft密码，不借用PCL/Prism等启动器client ID。上游应用接入受限时诚实阻断相应在线功能。

认证请求与资源请求分隔HTTP client配置；凭据仅发到允许的认证目标；重定向不传secret。调试模式也不打印Authorization、Cookie、XSTS、refresh/access token、device_code、授权code或PKCE verifier。客户端ID可以出现在设置诊断中，因为它不是secret。

4. 日志、隐私与保留

默认全部本地，无遥测、崩溃自动上传或AI自动发送。应用日志轮转：单文件10MiB、最多5份；运行日志默认保留30天/总量500MiB，清理只作用于launcher管理的副本，崩溃报告与用户导出单独保留。任务详细记录默认30天，摘要保留180天，可清空。

脱敏流水线：先按结构字段遮蔽secret→正则识别常见token/UUID/邮箱/IP/用户路径→替换为稳定占位符→用户预览。游戏日志可能含聊天/服务器地址，自动脱敏不能保证全部识别，因此导出前显示范围并允许删除行；不宣称“绝对匿名”。导出为本地ZIP，包含版本/Java/Loader/错误链与脱敏日志，不含完整存档、账号数据库或原始凭据。

未来AI入口：先本地摘要、明确提供商/发送内容/成本、逐次确认发送；结果标记为建议，不自动执行命令、删除Mod或上传更多文件。M7不得更改核心登录/下载策略。

5. PCL/.minecraft迁入

  1. 用户选择目录产生root令牌，后台只读扫描versions、各版本JSON、PCL/官方常见隔离目录、mods/config/saves/resourcepacks/shaderpacks/screenshots。
  2. 根据真实路径与文件结构辨认“共享gameDir/按版本隔离”，不只看PCL配置标记。共享saves与mods可能属于多个版本，展示归属不确定项让用户选择复制范围。
  3. 导入预览包括：实例名、MC与Loader、源gameDir、待复制大小、共享/未知内容、需要重新下载的依赖、不可迁移的认证。发现重复文件按hash去重；未知外部启动脚本仅列出，不执行。
  4. 默认完整复制用户可变内容；可选择不复制screenshots/logs，大型saves默认保留且告知空间。版本与依赖可引用已验缓存，但不以“导入成功”替代校验。
  5. 写入新UUID目录和journal；校验每个复制文件的大小+hash，源文件在扫描后修改则重新计算预览，不能边游戏运行边迁移存档。
  6. 重新登录；Java路径重新探测。源PCL配置不直接覆盖设置；不导入PCL账号、注册表、明文token、自定义可执行主页。
  7. 首次启动通过后展示成功与源目录位置；绝不自动清理源目录。迁移失败删除/回收仅限本次新建目标，源保持完整。

v1不支持原地接管为默认模式；后续如增加“外部实例关联”，必须有独立ADR和双启动器竞争写入检测。

6. 应用升级与schema迁移

DB与文件格式均有schema_version。迁移开始前关闭写队列、检查空闲空间、SQLite在线备份并验证能打开、记录MigrationRecord。纯DB迁移单事务；文件布局迁移使用journal和可恢复复制，不能用一次性启动脚本递归改用户目录。

迁移失败自动保持旧DB备份与旧数据，进入只读恢复页；只在新schema已验证后切换指针。旧程序遇到更高schema拒绝写入。降级只允许使用对应备份，不能把新字段删掉装作兼容。备份建议保留最近3次schema迁移及7天内用户显式备份，删除前检查回退依赖。

全局数据根迁移：冻结写入/要求游戏退出→空间和卷ID检查→复制与hash验证→原子切换DB root记录→重建投影→验证一次启动→旧根保留至少7天，用户明确清理。失败回旧指针。缓存可重建，saves/config不可通过“修复下载”恢复。

7. 备份恢复与灾难恢复

备份分三种：配置/DB备份、实例配置+Mod清单备份、完整实例含存档快照。创建存档快照必须游戏退出；不承诺运行时一致备份。快照带完整文件清单和sha256、schema、创建时间、来源实例revision；v1恢复先预览差异并固定为新实例，不提供覆盖当前实例的入口。

DB损坏时：保留原文件→只读诊断→检查最近备份→恢复备份并扫描lock投影→列出可能丢失的任务/设置→重新审计缓存引用。找不到备份时只从本启动器有效lock与目录重建；不得删除未知目录。缓存损坏只隔离并补下，不能清空整个数据根。

规划端点：Microsoft consumers OAuth authorize/token；user.auth.xboxlive.com/user/authenticate；xsts.auth.xboxlive.com/xsts/authorize；api.minecraftservices.com/authentication/login_with_xbox；entitlements/mcstore与minecraft/profile。这些需要在M0/M3用自有获准client ID确认参数、scope、权限与Game Pass行为；本包未实测敏感POST，也不借用其他启动器ID。

R20 Minecraft Java支持目录 的搜索索引列出Game Service API Review/Application主题，但当前网页正文动态加载，未成功读取该文章完整审批条件。因此“自有应用是否获准”是明确开放项，不能写成“个人使用自动免审批”。M0交付须记录实际申请入口与结果；403需区分接入、账号与服务状态。

6. Modrinth、整合包与CurseForge（A/B）

R21 API总览：公开读请求通常无需账号token；请求需独特User-Agent；根据rate limit响应头调速。文档当次说明300次/分钟，本设计本地预算更保守，并以服务端实际响应为准。GET /v2/ 在本次返回404；这不代表全部服务不可用，应使用有效业务端点做探测。

R22 搜索 定义facets；R23 版本列表 提供files与dependencies；R24 Hash识别 提供本地文件映射。本次search(sodium,limit1)与project/sodium/version(1.21.1,fabric)均GET200，后者返回22条样本；版本候选不等于依赖已求解。

R25 mrpack格式：清单、文件hash、环境与覆盖目录是安装依据。设计按客户端环境处理，先路径预审后下载与应用覆盖；未知必需依赖阻断。

R26 CurseForge API 需要API key；文件下载能力可能受上游策略限制。设计不承诺所有CF整合包一键下载，提供手动补齐清单。未取得key、未实测下载权限，故仅列条件支持。

7. Tauri/Windows（B/C）

R27 Capabilities 用于限制窗口/IPC权限，但Rust自定义命令仍须做业务与输入校验。R28 Windows Installer 描述WebView2依赖与Windows打包。设计采用每用户安装、WebView2检测/修复提示，不默认系统权限；签名与自动更新分发不在个人版首轮范围。

技术版本号只锁大方向Tauri2/React/TypeScript/Rust；真正开始实施时检查当前兼容版本并锁依赖，不能把研究日称为“所有依赖最新”。本次本机为macOS，未进行Windows 11的进程/凭据/WebView2运行验证。

8. 研究结论与实施前复核清单

  • 下载保留为产品主路径，不能因PCL的新版本变化而删去FR-03。
  • 版本与Java均按元数据，精确Loader约束和固定fixture复核；网页概括冲突时停止并查具体版本。
  • Mod兼容与更新按具体文件求交，保留旧文件回滚；整合包越界检查先于创建输出。
  • OAuth成功、Minecraft API接入、权益、profile与实际启动是不同的验收门。
  • M0优先消除账号接入、安装器行为、Windows路径/凭据这三类高风险未知，再推进主闭环。
  • 后续agents每次重新联网核实时补checked_at、来源与差异记录，不覆盖原始研究证据；本次快照仅供解释设计，不作为永久版本列表。

5. 状态与组件契约

按钮：normal/hover/pressed/focus/pending/disabled；pending保留宽度、禁重复提交、文字明确“生成计划中”。焦点3px，offset3px。禁用按钮的原因在近邻文本或aria-describedby，不能只有灰色。任务Committing时显示“正在保存安装结果”，无可点击的暂停/取消。

输入：独立label、help与error；错误不替换label，提交聚焦首个错误；字符计数按Unicode规则。select/radio真实暴露checked/selected。标签页用tablist/tab/tabpanel与左右键/Enter，或导航链接语义；不能混用“按钮外观”和不存在的aria角色。

模态：打开聚焦标题或首个合理输入；Tab/Shift+Tab圈定，背景inert，Esc关闭不产生副作用的预览；关闭返回触发者（触发者已卸载则页面h1）。危险操作默认焦点取消。后端提交已接受时关闭弹窗只关闭视图，不取消任务。

设置：草稿跨分类保留；离页提供保存/放弃/继续编辑；主题即时预览，放弃恢复。保存失败保留草稿、错误和旧持久值。原型能演示主要草稿行为；全部SettingsValues以11为准，不以画出的字段子集裁剪产品功能。

进度：未知总量不画百分比，显示“已下载X / 总量待确认”；暂停与离线速度为0；校验/安装用步骤或不定进度；失败展示错误码、影响和恢复按钮；结束结果常驻卡片，toast辅助显示3.4秒。下载状态不复用实例Ready标签。

5. Task / execution与资源锁

Task枚举：Queued、Running、Pausing、Paused、Retrying、Verifying、Installing、Committing、NeedsAction、Interrupted、Canceling、Succeeded、Failed、Canceled。Planned属于Plan，永远不是已提交Task。

TaskExecution：Active→Succeeded/Failed/Canceled/Interrupted；每Task最多一个Active；旧记录终态不可改。Paused/Retrying仍处于同一Active execution；应用崩溃记Interrupted结束旧execution，恢复时创建新execution并保留恢复来源ID。只有在重启审计确认旧execution实际上已完成提交时，将其结果记入恢复审计记录并展示任务Succeeded，不能删除或改写中断历史。retry_failed仅Failed可用，新execution.ordinal+1，重新获取实例mutation lease并检查原plan内容与base_revision；复用已验证对象，不改变固定版本。输入变化/计划需调整返回REPLAN_REQUIRED而非偷偷改计划。Canceled/Succeeded只能重新preview为新任务。Interrupted先按journal审计：确定已commit则补Finalized且执行完成；未commit可回滚或基于原计划继续；无法判断转NeedsAction。

Capabilities：Queued可pause/cancel；Running可pause/cancel；Pausing只cancel；Paused可resume/cancel；Retrying可pause/cancel；Verifying仅cancel；Installing在适配器safe_point可pause/cancel，否则只显示请求待停点；Committing无动作；NeedsAction可对应resolve/recheck及cancel；Interrupted可recover/cancel（先审计）；Failed可retry_failed；Succeeded/Canceled只读。pause/retry多击通过revision+幂等处理，不切换成相反动作。

锁顺序固定：全局maintenance→DataRoot→Instance（UUID排序）→Artifact（digest排序）。不可持DB写事务等网络/进程。实例mutation lease在接受有实例写意图的plan时持久获取；活动运行与它互斥；暂停任务继续占用，UI提供取消释放。Failed须已安全回滚才释放，现场未知为NeedsAction继续阻止启动。跨实例纯缓存下载按对象单写lease共享，取消一个订阅不影响其他订阅。租约续期5秒、过期30秒；应用单实例互斥锁先防重复宿主，启动恢复检查宿主身份，不能因30秒到期就覆盖仍在运行的Java/处理器输出。系统睡眠与时钟回拨后先审计。

run身份无法验证时Run=Unknown，保留阻塞性占用；用户只能重新探测/查看指引，不能直接“解除锁并覆盖”。在确认对应进程已退出后才能释放。账号移除如被活动run引用则返回ACCOUNT_IN_USE，保留secret到安全移除。

6. 事件协议与重连

持久Event仅记录状态、配置与终结结果；状态与事件在同一DB事务提交。全局event_id递增，但SQLite分配可能不连续，不依靠数值+1判断是否丢失。events.read从after_cursor取实际记录，以next_cursor作为消费水位。无过滤接口，前端接收后按实体分发；分页拿到has_more=false才追平high_watermark。

握手：先注册实时通知并缓冲→sync.snapshot获取同一读事务快照和cursor C→应用快照→events.read(after=C)补齐→按event_id去重处理缓冲→进入通知驱动补拉。订阅通知只做唤醒，5秒低频补拉兜底；前端隐藏时30秒，回到前台立即同步。保留事件7天且最多100000条，裁剪前保留低水位；太旧返回CURSOR_EXPIRED并重做握手。bootstrap只提供前200实例摘要，sync.snapshot则为所有实体返回最小revision索引及活动实体DTO，最大10000实例/1000活动任务，超过返回SNAPSHOT_LIMIT而非静默裁剪；完整列表详情用instance.list分页，不参与一致性基线。每页instance.list绑定查询版本，如revision索引改变则重新查该实体；不把不同时间分页称为原子快照。snapshot_id用于诊断，不依赖未定义的快照分页接口。

progress通知不写Event表、不提升entity_revision；带task_id、execution_id、progress_seq。相同execution仅接受更大seq；execution切换清掉旧进度。断线时progress来自TaskDTO checkpoint，进度允许回到最后落盘边界，不能把UI曾显示字节当已验证。通知发送4Hz上限；仅bytes_total已知才算百分比，进度100%仍可处于Verifying/Installing。

7. 文件提交与崩溃恢复判定

journal不是一次目录rename的假设。提交前完成全量计划路径预审、锁与目标指纹校验；manifest为每个entry保存old/new digest、staged/backup/target相对位置、动作与完成标记。journal每个步骤持久化并刷新；单文件替换可原子，不声称多个文件整体原子。游戏和其他写任务由lease隔离期间不可见中间态。

9. Agent集成与阶段门

实现者不能仅复制HTML及其内存逻辑。必须先将语义token映射为React组件，再按UI-ID接真实DTO；page/module owner不拥有改变协议的权力。每次完成必须交付成功、失败、取消/重启的证据及未通过项。无法满足现有契约时先提交设计差异，不通过删按钮、取消下载、吞错误、忽略hash或返回fake Ready来绕过。

基础门允许独立实现继续，认证门只阻塞依赖它的链路；这不是把认证标记已验收。M6收口必须AC01–40全部适用项通过。Quilt/旧版专项若未通过保持unverified；“核心承诺”仍为PRD的L1/L2，L3/L4不是新默认承诺。

页面、操作与实现追踪

基线2.0。此文由同包“设计契约/页面操作追踪.json”呈现；JSON保留规范命令名，不能把HTML中的演示函数名当Rust接口。每一行均为未来必须实现的闭环；原型列描述当前视觉示意范围，不表示产品功能完成。

1. 共同页面契约

  • 实例路由由instance_id驱动。首页当前实例、侧栏选择、详情、Mod、日志必须共享同一UUID上下文；显示名仅展示，不用于查找身份。无目标时显示选择实例，绝不静默回退到“远山生存”。
  • 所有读视图有Loading、Content、Empty、Error、Stale状态；Empty与Error不可共用“没有数据”。已有数据刷新时保留内容，顶部给更新时间与非阻断错误。
  • 所有变更有Idle、Validating、Preview、Submitting、Accepted或Rejected；Accepted转任务链接，不能直接改成“已安装”。一个用户提交意图沿重试复用同幂等key，修改内容后生成新key。
  • 危险按钮先显示范围与可恢复性；disabled旁必须有原因，不能只靠hover。进度卡的capabilities来自后端，而不是前端按中文标签猜。
  • 页内搜索防抖250ms、取消旧请求、按query+instance_id+revision去重；旧请求迟到不能覆盖新目标。表格默认名称升序，任务按创建时间降序，日志按行序升序。每页50，最大200；滚动不无限挂载1000行。
  • 路由切换只保留用户筛选与草稿；异步数据由快照更新。新页面主标题获得程序化焦点，侧栏保留aria-current。关键结果留在页内，toast只是辅助。

首次启动引导（P00）：选择本地数据根→读写/剩余空间检查→显示结果→写入配置；登录可稍后。无根授权不能commit安装。安装缺WebView2时由原生引导说明修复入口，不能依赖尚不可显示的WebView完成引导。

导入向导（D01）：选源→扫描进度→逐实例和共享目录范围选择→选择目标→差异与空间→确认→任务。未知归属不默认复制进所有实例；源变化要求重扫。

克隆升级（D02）：原实例快照→名称、目标MC/Loader构建与是否含存档→Mod保留/替换/移除差异→必需冲突解决→新实例计划。确认页包含“源不变；升级后的存档不保证可降级”。

回收站（D03）：设置/存储入口，显示原名称、删除时间、含存档、保留期限、大小；恢复先审计，目标ID冲突时要求新实例恢复；永久清理单独输入“永久删除”。到期只变为可清理，不自动销毁存档。

恢复中心（D04）：启动检测Interrupted/journal冲突后显示任务、最后安全阶段、保留数据位置、可恢复动作；除确定可自动完成的DB已提交投影外，先显示恢复摘要。无法判定文件所有权时只读保全并显示RepairRequired。

实例参数（D05）：Java（继承/自动/指定已验证runtime）、Xms/Xmx、窗口模式/尺寸、JVM高级参数白名单；字段旁显示有效值及来源。高级参数解析失败定位具体项；不能开放任意shell命令。

以上可以用原型的弹窗与组件规范组合实现，不授权agent省略步骤。缺图不代表可造新的默认行为；新增业务规则先补ADR与AC。
