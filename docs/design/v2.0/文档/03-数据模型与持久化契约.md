# 数据模型与持久化契约

这是逻辑数据字典与事务规范，不是SQL迁移文件。schema起始为1；后续实现可调整物理索引，但不能改变不变量。

## 1. 目录与真相源

默认配置根 `%LOCALAPPDATA%\KLauncher\`；默认数据根 `%USERPROFILE%\Games\KLauncher\`，首次启动可选其他本地NTFS卷。启动器安装目录与可变数据分开。首版不承诺网络盘/同步盘/可移动盘；检测到后说明风险并要求改用本地目录。

```text
配置根/
  settings.json                 全局设置的可读导出，不含秘密
  launcher.db                   元数据、任务、配置真相源（WAL）
  backups/                      DB与配置迁移前备份
  logs/                         应用日志（轮换）
数据根/
  objects/<algorithm>/<prefix>/<digest>  不可变已校验缓存
  assets/indexes/ 与 assets/objects/     游戏兼容投影（可重建）
  libraries/ 与 versions/               元数据及依赖兼容投影
  runtimes/<provider>-<build>-x64/        托管Java（不改系统PATH）
  instances/<uuid>/
    instance.lock.json                  组件/内容锁定导出与恢复凭据
    game/                              saves,mods,config,resourcepacks,shaderpacks等
    runs/<run-id>/                      本次日志、natives、脱敏启动摘要
  staging/<operation-id>/               下载/解压/处理器工作区（同目标卷）
  trash/<deletion-id>/                  删除回收（默认7天）
  exports/                             用户主动导出
```

DB是真相源，lock文件是带revision与digest的可恢复投影。DB事务提交后生成临时lock并原子替换；中断导致lock落后时按DB重建；如果DB损坏，只能进入只读恢复模式，用户确认后从经过schema/路径/摘要校验的lock重建元数据。不得依据时间戳把外部lock覆盖进DB。

内容缓存与mutable game目录不得使用可写硬链接；v1依赖兼容投影统一复制，不使用hardlink/junction/symlink；只读属性不是可靠的隔离边界。运行前检查对象摘要。外部游戏可能修改库，因此必须允许投影重建，不把它作为缓存真相。

## 2. 通用字段

ID采用UUID；外部provider ID保留原样字符串，不转数字。时间存UTC RFC3339，UI按系统时区显示；elapsed使用单调时钟。size以u64字节表示、UI以MiB/GiB显示；所有IPC中的字节数、revision、event_cursor、progress_seq统一为十进制字符串（即便小于JS安全整数），禁止按数值大小切换类型。digest存algorithm+规范化小写hex。路径存path_id或根内相对路径；UI显示路径不直接作为授权路径。

revision为递增u64；所有变更需expected_revision。enum未知值在读展示时标记Unsupported，在执行时阻断，不能默认成Ready。可选值缺失与空字符串区分。

## 4. 实例锁文件示例（说明性）

```json
{
  "schema_version": 1,
  "instance_id": "2f37a2bf-ff1d-45ae-9f44-71f352c296de",
  "revision": 7,
  "name": "远山生存",
  "minecraft": { "id": "1.21.1", "metadata_ref": "snapshot-id" },
  "loader": { "kind": "fabric", "version": "示例：实施时固定已验证构建", "metadata_ref": "snapshot-id" },
  "java": { "mode": "auto", "required_major": 21 },
  "memory_mib": 4096,
  "content": [ { "path": "mods/example.jar", "enabled": true, "hashes": { "sha512": "示意，实际必须为完整hex" }, "provider": "modrinth", "project_id": "project-id", "version_id": "version-id" } ],
  "source": { "kind": "created", "import_id": null }

```

示例不是可直接导入的fixture；implementation必须使用真实完整摘要。lock不含绝对本机私有路径、token、邮箱、代理密码。外部同名文件变化将触发“外部修改待协调”，不能覆盖。

## 5. 设置层级与验证

默认值→全局设置→实例显式覆盖→本次启动临时覆盖。UI要显示“继承”与当前有效值，取消覆盖恢复继承。支持字段：语言/主题/缩放、默认数据根、下载总并发(1–16)/单域(1–8且≤总量)、限速(0不限速)、代理(system/direct/custom)、缓存预算、Java policy、内存、窗口尺寸、关闭行为、日志保留。

内存：最小512MiB、步进256MiB、xms≤xmx；默认值以4GiB与可用物理内存预算取小，必须给OS预留至少max(2GiB,25%RAM)，无法满足需求时提示而不是偷偷超配。自定义JVM参数高级入口逐项记录，拒绝覆盖认证、classpath、主类与工作目录；不执行任意前后置脚本。

代理凭据存凭据服务，设置只保存credential_ref；v1下载与认证代理共用已保存配置，分别持有隔离HTTP client；分流代理设置留待独立ADR。TLS错误没有“忽略证书”开关。

## 6. 关键事务与不变量

- 每实例最多一个被接受的变更作业，commit计划时获取持久mutation lease直到成功/取消/失败安全回滚；游戏运行lease与该lease互斥。失败若保留未回滚现场仍占锁并转NeedsAction。无实例写意图的纯缓存预取可并发。第二个写/启动返回INSTANCE_BUSY并链接占用任务；不等到文件交换才发现冲突。
- task.state=Succeeded要求所有必需步骤Succeeded且实例提交journal已完成，不能只看下载字节100%。
- Instance=Ready要求已提交锁文件revision的所有必需组件可解析、必需对象存在并验过；运行前仍做廉价存在/指纹检查，必要时重哈希。
- 登录密钥永不进SQLite/lock/event/前端；account.remove同时删除凭据引用与secret，失败记录可重试清理，不显示“已完全删除”。
- 删除实例只移走自己UUID目录；不按用户可变名称递归删除。共享assets/libraries对象由引用计数+扫描GC回收。
- GC先mark引用（活动任务、plan、实例、回收站/备份），再隔离候选，过24小时宽限期二次确认后删除；与下载和提交共享锁。引用计数不得单独作为唯一删除依据。
- DB外键开启，WAL、busy timeout、短事务；大文件I/O与网络不得在DB写事务内等待。
- 设置保存、事件记录、revision增加同事务；写失败保留旧值，UI不能先显示永久成功。

## 7. 文件系统与DB跨介质提交

不能假设SQLite事务会回滚文件。采用journal：Prepared（目标与旧manifest）→FilesStaged（所有文件已验证）→FilesSwapped（同卷原子rename/replace，旧文件移rollback目录）→DbCommitted（更新实例revision与引用）→Finalized（写lock投影、清理旧文件）。启动恢复逐条核查journal：DB未提交时回滚或继续已验证步骤；DB已提交时补齐投影，不回退已确认revision。发生无法判断的外部改动则RepairRequired，保留两份文件供核对。

跨卷迁移一律复制→校验→切换root指针→旧目录保留回退期，不将“跨卷move”当原子操作。
