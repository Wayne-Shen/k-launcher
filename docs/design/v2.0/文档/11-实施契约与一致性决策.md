# 实施契约与一致性决策

基线2.0 / contract_version=1 / schema_version=1。这里是设计协议与数据字典，**不是已经生成的后端、SDK或数据库代码**。补齐1.0中会导致不同agent实现分叉的默认值、接口与恢复判定。

## 1. 规范优先级与变更

用户已确认范围（下载刚需、仅Win11个人用、AI后置）优先。产品名统一为K Launcher，实施与设计保存在同一私有仓库。行为冲突按本文件和12文档的细化决策→01–08原业务约束→原型示例处理；视觉按“设计契约/视觉令牌.json”→09尺寸与状态→HTML视觉参考。契约JSON与本文同级，若发现不一致必须先修正文档，不得自行选一个有利于通过测试的版本。

冻结文件：命令目录.json（65个规范命令）、页面操作追踪.json（38组用户操作）、视觉令牌.json。未来Rust函数名可用snake_case映射，但对外协议名称不能由各agent重新命名。样例账号/版本/速度/Java辅助函数不是实现规则。

T06输出《实施基线记录》，包括：设计版本/包SHA256、目标Windows环境、依赖确切版本、65命令到Rust入口映射、每个DTO物理类型映射、SQLite索引/迁移策略、固定MC/Loader/Java样本、开放项与阻塞任务。局部技术选择可自主完成；改变行为、范围或不变量先记录ADR及受影响AC。没有Windows或API批准时如实标阻塞，不替换为“网页能点通”。

## 2. 统一请求、返回与幂等

| 类型 | 必需字段与含义 |
|---|---|
| Request | contract_version:1；request_id:UUID；payload:命令目录规定的对象；变更命令另有idempotency_key:UUID |
| Success | ok:true；request_id；data:规定DTO；warnings:Issue[]（默认空） |
| Failure | ok:false；request_id；error:ErrorDTO；data不得同时出现 |
| ErrorDTO | code:string；phase:string；retryable:boolean；message_key:string；field_errors:FieldError[]；actions:ActionDescriptor[]；correlation_id:UUID；details_redacted:object（白名单字段）；cause_code?:string |
| FieldError | field:白名单字段路径；code:string；message_key:string；constraints:JSON标量对象 |
| ActionDescriptor | id:retry/repreview/login/free_space/choose_path/view_log/open_task；enabled:boolean；disabled_reason?:string；target_id?:UUID；不含可执行代码/自由命令/任意URL |
| Issue | code:string；severity:info/warning/blocking；message_key；params:脱敏标量对象；acknowledgement_id?:string |

未知请求字段、未知enum与错误类型直接拒绝，不做宽松类型强转。UUID为带短横线小写字符串；DecimalString为非负十进制整数字符串（零为“0”，无前导零）；金额不适用，本产品无支付。时间为UTC RFC3339。空值明确用null；缺省只用于表格标?且写明默认的字段。所有列表空值为[]。请求总payload≤1MiB，日志不通过命令一次塞入。

变更mode=mutate必须带幂等key；plan/read/interaction不强制。计划不写游戏文件，允许持久保存短期计划。幂等scope=(当前本地用户,规范命令名)；收据保存canonical payload的SHA256和结果引用。请求字段排序稳定、UTF-8、禁止浮点和NaN；digest字段本身不参与自身摘要。复用key+相同payload返回同结果，即使expected_revision已旧也先命中收据；同key不同payload返回IDEMPOTENCY_CONFLICT。任务存在期间收据不清理，任务归档后至少保留180天；同一次点击的网络重试不能换key。request_id只用于诊断，每次传输可新建。

**计划重复点击**：plan_id只能被commit一次，DB唯一约束。即使用不同idempotency_key重复提交同plan，也返回首次task_id；不同payload/digest则拒绝。canonical digest由Rust生成，React只原样回传。取消后重新安装要生成新plan，不复活旧plan。

## 5. Task / execution与资源锁

Task枚举：Queued、Running、Pausing、Paused、Retrying、Verifying、Installing、Committing、NeedsAction、Interrupted、Canceling、Succeeded、Failed、Canceled。Planned属于Plan，永远不是已提交Task。

TaskExecution：Active→Succeeded/Failed/Canceled/Interrupted；每Task最多一个Active；旧记录终态不可改。Paused/Retrying仍处于同一Active execution；应用崩溃记Interrupted结束旧execution，恢复时创建新execution并保留恢复来源ID。只有在重启审计确认旧execution实际上已完成提交时，将其结果记入恢复审计记录并展示任务Succeeded，不能删除或改写中断历史。retry_failed仅Failed可用，新execution.ordinal+1，重新获取实例mutation lease并检查原plan内容与base_revision；复用已验证对象，不改变固定版本。输入变化/计划需调整返回REPLAN_REQUIRED而非偷偷改计划。Canceled/Succeeded只能重新preview为新任务。Interrupted先按journal审计：确定已commit则补Finalized且执行完成；未commit可回滚或基于原计划继续；无法判断转NeedsAction。

Capabilities：Queued可pause/cancel；Running可pause/cancel；Pausing只cancel；Paused可resume/cancel；Retrying可pause/cancel；Verifying仅cancel；Installing在适配器safe_point可pause/cancel，否则只显示请求待停点；Committing无动作；NeedsAction可对应resolve/recheck及cancel；Interrupted可recover/cancel（先审计）；Failed可retry_failed；Succeeded/Canceled只读。pause/retry多击通过revision+幂等处理，不切换成相反动作。

锁顺序固定：全局maintenance→DataRoot→Instance（UUID排序）→Artifact（digest排序）。不可持DB写事务等网络/进程。实例mutation lease在接受有实例写意图的plan时持久获取；活动运行与它互斥；暂停任务继续占用，UI提供取消释放。Failed须已安全回滚才释放，现场未知为NeedsAction继续阻止启动。跨实例纯缓存下载按对象单写lease共享，取消一个订阅不影响其他订阅。租约续期5秒、过期30秒；应用单实例互斥锁先防重复宿主，启动恢复检查宿主身份，**不能因30秒到期就覆盖仍在运行的Java/处理器输出**。系统睡眠与时钟回拨后先审计。

run身份无法验证时Run=Unknown，保留阻塞性占用；用户只能重新探测/查看指引，不能直接“解除锁并覆盖”。在确认对应进程已退出后才能释放。账号移除如被活动run引用则返回ACCOUNT_IN_USE，保留secret到安全移除。

## 6. 事件协议与重连

持久Event仅记录状态、配置与终结结果；状态与事件在同一DB事务提交。全局event_id递增，但SQLite分配可能不连续，**不依靠数值+1判断是否丢失**。events.read从after_cursor取实际记录，以next_cursor作为消费水位。无过滤接口，前端接收后按实体分发；分页拿到has_more=false才追平high_watermark。

握手：先注册实时通知并缓冲→sync.snapshot获取同一读事务快照和cursor C→应用快照→events.read(after=C)补齐→按event_id去重处理缓冲→进入通知驱动补拉。订阅通知只做唤醒，5秒低频补拉兜底；前端隐藏时30秒，回到前台立即同步。保留事件7天且最多100000条，裁剪前保留低水位；太旧返回CURSOR_EXPIRED并重做握手。bootstrap只提供前200实例摘要，sync.snapshot则为所有实体返回最小revision索引及活动实体DTO，最大10000实例/1000活动任务，超过返回SNAPSHOT_LIMIT而非静默裁剪；完整列表详情用instance.list分页，不参与一致性基线。每页instance.list绑定查询版本，如revision索引改变则重新查该实体；不把不同时间分页称为原子快照。snapshot_id用于诊断，不依赖未定义的快照分页接口。

progress通知不写Event表、不提升entity_revision；带task_id、execution_id、progress_seq。相同execution仅接受更大seq；execution切换清掉旧进度。断线时progress来自TaskDTO checkpoint，进度允许回到最后落盘边界，不能把UI曾显示字节当已验证。通知发送4Hz上限；仅bytes_total已知才算百分比，进度100%仍可处于Verifying/Installing。

## 7. 文件提交与崩溃恢复判定

journal不是一次目录rename的假设。提交前完成全量计划路径预审、锁与目标指纹校验；manifest为每个entry保存old/new digest、staged/backup/target相对位置、动作与完成标记。journal每个步骤持久化并刷新；单文件替换可原子，不声称多个文件整体原子。游戏和其他写任务由lease隔离期间不可见中间态。

| 检测到的事实 | 恢复决定 | 实例状态 |
|---|---|---|
| Prepared/FilesStaged，DB仍base_revision，目标旧digest匹配 | 清理/保留staging，原实例不变；可重新执行 | 原Ready或新Draft |
| 部分FilesSwapped，DB仍base_revision，目标为已知new或old、backup完整 | 按manifest逆序恢复old，验证全部；原计划可重试 | 回滚完成后原状态 |
| FilesSwapped完成，DB仍base_revision且所有新文件匹配 | 默认回滚；只有用户明确“继续恢复”且原计划有效才提交DB | 审计中不可启动 |
| DB=target_revision、commit标记已落盘，投影缺失 | 根据DB补lock与Finalized；不得回退已确认revision | 完成后Ready |
| DB为其他revision，或任何target/backup与记录两种digest均不符 | 保留所有副本，停止自动恢复，记录文件级冲突 | RepairRequired |
| 中断发生在root迁移 | DB root指向旧根则继续旧根；指向新根则验证新根并补投影；两端不完整则只读 | 不能仅按盘符切换 |

删除/restore/purge/GC/备份恢复也使用有kind的journal；永久purge没有文件回滚承诺，因此先确认无引用并只删清单中的准确对象，失败可重试剩余项。GC quarantine24h后重新mark；存档不进入cache GC。可回滚的旧Mod位于操作rollback目录，直到事务Finalized后进入保留7天的内容回收记录，不与用户实例删除混为一条Deletion。

## 8. 错误分类与禁止的降级

03/05的错误继续有效；下列补齐协议类错误。任何ErrorDTO.actions只允许枚举中的安全意图，由UI映射相应命令。

| code | retryable / 恢复 | 不得做 |
|---|---|---|
| CONTRACT_UNSUPPORTED / VALIDATION_FAILED | false；升级协议或修正字段 | 静默忽略未知字段 |
| IDEMPOTENCY_CONFLICT | false；核对用户意图后新key | 覆盖原收据 |
| REVISION_CONFLICT | false；保留草稿、重拉快照、重新预览 | 盲重试覆盖 |
| PLAN_EXPIRED / PLAN_DIGEST_MISMATCH / REPLAN_REQUIRED | false；重新预览确认 | 后端修改原计划继续 |
| PATH_GRANT_EXPIRED / PATH_IDENTITY_CHANGED | false；重新选择授权路径 | 根据display_path继续 |
| INSTANCE_BUSY / ROOT_MAINTENANCE / ACCOUNT_IN_USE | false；链接占用者、等待完成或取消自己的任务 | 强制解锁/杀未知进程 |
| CURSOR_EXPIRED | true；重做快照握手 | 清空用户数据 |
| SNAPSHOT_LIMIT | false；保留数据，按ADR评估增加容量或分区协议 | 静默裁剪一致性基线 |

| SOURCE_CHANGED / INSTANCE_EXTERNAL_CHANGE | false；重新扫描与差异确认 | 覆盖外部新文件 |
| AUTH_INTEGRATION_UNAVAILABLE | false；M0接入门待解决 | 借用其他启动器身份或伪成功 |

## 9. Agent集成与阶段门

每一阶段先交接“本阶段输入/输出/不可变字段/AC列表”；UI实现与Rust实现使用同一命令目录和版本化fixture。fixture只能存无秘密的合成/裁剪数据，必须标记来源与checked_at；真实运行配置不得静默落回fixture。

实现者不能仅复制HTML及其内存逻辑。必须先将语义token映射为React组件，再按UI-ID接真实DTO；page/module owner不拥有改变协议的权力。每次完成必须交付成功、失败、取消/重启的证据及未通过项。无法满足现有契约时先提交设计差异，不通过删按钮、取消下载、吞错误、忽略hash或返回fake Ready来绕过。

基础门允许独立实现继续，认证门只阻塞依赖它的链路；这不是把认证标记已验收。M6收口必须AC01–40全部适用项通过。Quilt/旧版专项若未通过保持unverified；“核心承诺”仍为PRD的L1/L2，L3/L4不是新默认承诺。
