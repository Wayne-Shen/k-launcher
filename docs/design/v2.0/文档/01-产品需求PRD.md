# K Launcher · Minecraft Java 启动器 PRD

版本：设计基线 2.0 · 2026-10-22（Asia/Shanghai）

状态：供分阶段实现；本交付不包含产品代码。产品名“K Launcher”，按用户确认固定。

平台：Windows 11 x64 桌面；Rust + Tauri 2 + React + TypeScript。ARM64 原生支持不属于首版验收范围。

## 1. 已确认的目标与前文审视

用户已确认：仅 Windows 11；本地个人使用、不对外分发；逐步覆盖 PCL2 核心能力；必须能下载 Minecraft；AI 后置；需要详细规格与真实视觉设计，由其他 coding agents 实现。

此前聊天的用户消息已读取，三段助手答复均仅返回内容引用标记，没有可审阅正文。因此这里不声称“验证了旧架构”。本包重建可追踪的设计基线；若后续获得旧全文，按 ADR 流程合并，不能覆盖上述硬性约束。

产品价值：从“我要玩某个版本/整合包”到“知道安装了什么、发生了什么、怎样恢复”的本地工作台。下载、安装、实例、Mod、Java、登录与启动组成完整闭环。下载不是辅助入口，也不能被“只导入已有游戏”替代。

P0＝首个可用闭环必须具备；P1＝核心覆盖阶段必须具备；P2＝完成核心后增强。P0/P1 是功能优先级，M0–M6 是执行阶段，见任务清单。

|---|---|---|---|

## 3. 支持矩阵与完成定义

| 层级 | 计划验证组合 | 策略 |
|---|---|---|
| L1 首版承诺 | 原版 1.20.1/Java17，1.21.1/Java21，26.1/Java25 | 全量下载、首次启动到主菜单、断网重启验证 |
| L2 核心承诺 | Fabric 1.21.1；Forge 1.20.1；NeoForge 1.21.1 | 固定经过测试的 Loader build；版本从上游查询，不写死原型示例 |
| L3 旧版扩展 | 1.12.2/Java8、其他老版及 Quilt | M4 专项样例通过后标记支持；否则“尚未验证”，不承诺自动安装成功 |
| L4 实验 | 最新快照、新 Java/新 Loader | 默认隐藏，用户开启实验版本后可见；元数据能解析不等于已验收 |

官方 26.1 已要求 Java25，不能沿用“新版本全部 Java21”的旧经验。上述版本是固定验收样本，不表示它们是当前最新版本。官方变动见研究文档 [R04]。

首个可用版完成＝在干净 Windows 11 用户环境下，不手动拼接文件，完成目录设置→登录→选择正式版→下载 Java/客户端/资源→创建实例→启动到游戏主菜单→关闭后再次启动。若自身 client ID 未获 Minecraft API 接入，M3 不能标记通过，其他阶段可以继续，不用假账号绕过。

## 4. 核心用户旅程

### J1 从零安装并游玩
1. 打开应用：读取本地数据；无实例时显示简明三步引导，先选择数据目录，再登录/浏览版本。
2. “安装游戏”：正式版默认选中，显示列表更新时间与来源；快照需主动开启。
3. 选择版本→可选一个兼容 Loader→实例名称与隔离目录→Java/空间预检。
4. 右栏显示安装摘要：下载估算、缓存复用、预计磁盘占用、Java、资源来源；未知大小显示“估算中”，不能显示 0。
5. “确认并安装”生成不可变安装计划；点击只创建一个任务。关闭向导不取消任务。
6. 下载→校验→构建→提交实例；期间可以浏览其他页面。
7. 完成进入实例详情；“启动游戏”预检账号与文件，启动后显示“运行中”和日志入口。

### J2 给既有实例装 Mod
从实例“Mod 管理”进入，默认“已安装”；“发现 Mod”继承 MC/Loader 筛选。选中项目后展示版本、依赖、来源与更新范围；安装前一屏确认必需依赖。可选依赖默认不选。冲突或没有客户端兼容版本时阻止确认。下载不立即替换正在使用的文件；提交后更新锁文件。更新失败保留旧版。

### J3 下载失败与恢复
任务卡显示阶段、已验证文件数、已传输字节、速度、来源与可执行操作。网络错误自动有限退避；超限转“需要处理”，显示最后错误和“重试失败项”。磁盘不足不盲重试，允许“更改目录并重新计划”或清理后继续。重启应用显示恢复提示，不自动运行未知状态的安装处理器。

### J4 老实例迁入
选择 PCL 或 .minecraft 根目录→只读扫描→列出隔离方式、MC/Loader、大小、未知内容→选择实例和复制目标→核对磁盘空间→复制与校验→修复缺失依赖→用户重新登录→首次启动。源目录不变；不迁移注册表、凭据、PCL 可执行配置脚本。

## 6. 交互规则与文案

- 用户显示名与磁盘目录 ID 分离；名称 1–64 字符，去首尾空格，禁止空名；内部目录只用 UUID，不因重命名改路径。
- 全局默认：自动匹配 Java、实例内存 4 GiB（设备允许时）、下载总并发8/单域4；这些是产品默认值，需在 Windows 性能验收后调整，不宣称最优。
- 任何“安装”显示目标实例和影响文件数；任何删除显示是否含 saves，并默认进入应用回收站，可恢复7天。清理永久删除需再次确认范围。
- 启动前 Esc 取消预检；启动进程后 Esc 不杀进程。停止游戏先请求正常关闭，超时再显示强制结束确认。
- 离线浏览与已有文件校验可用。仅先前成功验证的同一账号可进入受限离线启动路径；明确显示“离线，本次不刷新授权”，不能把 API403 或无权益转为离线成功。是否能运行取决于游戏版本，见状态机。
- 启动按钮旁持久在线账号与实例信息；登录失效不偷偷改用其他账号。
- 所有失败提示按“发生了什么→影响→可执行操作→详情码”组成。例如：“磁盘空间不足，安装尚未提交。释放至少 2.4 GiB 后继续。DISK_SPACE_LOW”。
- 原型所有数据、速度、版本组合均为演示；登录/启动/网络/安装只演示交互，不执行真实系统操作。

## 7. 非功能需求与测量办法

| ID | 指标/预算 | 测试条件 |
|---|---|---|
| NFR-01 | 本地首页冷开可交互≤2.5秒；热开≤1秒，目标值 | Win11 x64、16GB、SSD、100实例；以20次 p95计；网络不阻塞首屏 |
| NFR-02 | 空闲工作集≤200MiB目标；下载时≤350MiB目标 | WebView2含子进程；持续10分钟测 p95；超标需记录原因与优化任务 |
| NFR-03 | 1000 Mod列表筛选 p95≤200ms | 索引已加载；不在主线程解析JAR；列表虚拟化 |
| NFR-04 | 下载/哈希/解压期间界面响应≤100ms目标 | 1万个资源文件；限并发I/O；仅节流显示事件 |
| NFR-05 | 不得把未校验文件标记可用；崩溃恢复不丢存档 | 任务每个提交边界注入终止；全部安全性用例必须通过 |
| NFR-06 | 100/125/150/200%缩放，键盘完整操作 | 最小窗口1100×720 DIP；超出区域内部滚动；深色/高对比按系统适配 |

## 8. 决策与待验证项

已定：SQLite为元数据真相源；实例显式隔离；共享缓存只读；下载后原子提交；原生账号凭据存储；登录走系统浏览器；AI不进入核心依赖；普通用户权限安装运行。

仍需 M0 证据：自有 Microsoft client ID 与 Minecraft API 权限；Win11 设备CPU/内存；代理环境；Forge/NeoForge 安装器兼容样例；Adoptium固定Java构建可用性；实际旧实例目录。缺失时先用固定夹具完成模块设计，不降低验收门槛。

## 9. 成功标准

核心完成以“验收矩阵全部 P0/P1 通过”为准，不以页面数量或能弹出Java窗口为准。每次交付都必须附真实Windows结果、固定版本/Loader/Java构建号、故障恢复证据、已知限制和可复现步骤；与原型不同的交互必须说明依据。
